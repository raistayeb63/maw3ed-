إعداد الموقع ليتبادل الطلبات بين الهاتف وجهاز الطبيب

1. أنشئ مشروعاً جديداً في Supabase وانتظر حتى تصبح قاعدة البيانات جاهزة.
2. افتح SQL Editor في المشروع، أنشئ استعلاماً جديداً، والصق محتوى ملف supabase-setup.sql ثم اضغط Run.
3. من Project Settings > API انسخ Project URL وPublishable key (أو anon/public key القديم). لا تنسخ service_role/secret key أبداً.
4. افتح script.js وعدّل أول متغيرين:
   SUPABASE_URL = رابط مشروعك
   SUPABASE_ANON_KEY = Publishable key
   احتفظ بعلامتي الاقتباس حول القيمتين.
5. في Authentication > Users أنشئ حساب بريد إلكتروني وكلمة مرور لكل طبيب. لا تضع كلمات المرور في ملفات GitHub.
6. لكل طبيب، انسخ User UID من Authentication > Users ثم أضف ربطه في SQL Editor، مع اختيار المعرف الصحيح من القائمة d1 إلى d6:
   insert into public.doctor_accounts (user_id, doctor_id)
   values ('ضع-User-UID-هنا', 'd1');
   مثال: الطبيب د.طلبة نجيبة هو d1، د.بوهنشير مبروكة d3، د.بوقصة طارق d2، د.رمضاني رمضان d4، د.تريكي ايمان d5، د.علوش ابراهيم d6.
7. من Database > Publications فعّل Realtime لجدول appointments ضمن publication المسماة supabase_realtime.
8. ارفع index.html وstyle.css وscript.js وsupabase-setup.sql إلى GitHub Pages. ملف SQL لا يلزم أن يكون منشوراً للعامة؛ بعد تشغيله يمكنك حذفه من المستودع.
9. افتح الموقع عبر https، أرسل طلباً من هاتف، ثم سجّل دخول الطبيب على جهاز آخر. تظهر الطلبات للطبيب فوراً، وتُحفظ حالة الرد والوقت على قاعدة البيانات.

ملاحظات:
- دليل الأطباء وعناوينهم موجودة في قائمة DOCTORS في script.js؛ عدّلها عند الحاجة، ولا تضف بيانات دخول إليها.
- طلبات المريض وحالة الطلب تظهر في صفحة «طلباتي» على الجهاز الذي أرسل الطلب، لأنها تستخدم مفتاح متابعة محفوظاً محلياً في ذلك الجهاز.
- سياسات قاعدة البيانات تمنع المستخدم المجهول من قراءة سجل المرضى؛ الطبيب المسجل يرى طلبات المعرّف المرتبط بحسابه فقط.
- بعد تعديل بيانات الاتصال أو أي ملف، ارفع النسخ الجديدة وانتظر انتهاء نشر GitHub Pages.
